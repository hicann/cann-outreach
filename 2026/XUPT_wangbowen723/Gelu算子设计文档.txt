Gelu 算子设计文档

1. 需求背景（required）

1.1 需求来源
昇腾 NPU 算子开发任务：使用 Ascend C 编程语言实现 Gelu（Gaussian Error Linear Unit）算子，对标深度学习框架中 GELU 激活函数的标准实现，基于 Ascend 910B 硬件平台完成算子设计、开发与验证。

1.2 背景介绍

1.2.1 Gelu 算子实现
本算子为新增算子，基于 Ascend C 编程语言实现，采用算子工程框架（op_host + op_kernel 分离结构）：
- op_host：算子定义（OpDef 注册）、InferShape、InferDataType、Tiling 函数
- op_kernel：Ascend C kernel 实现（`KernelGelu` 类 + `gelu` 核函数入口）
- 支持硬件：Ascend 910B（`ascend910b`）

1.2.2 Gelu 算子 TBE/现有实现现状分析
GELU 是 Transformer 架构中广泛使用的激活函数，标准数学定义为：
```
gelu(x) = x * Φ(x) = 0.5 * x * (1 + erf(x / sqrt(2)))
```
其中 Φ(x) 为标准正态分布的累积分布函数（CDF），erf 为误差函数。

通过对 Gelu 算子的功能分析，当前支持的能力如下：

| 参数 | 参数含义 | 数据类型 | 支持数据类型 | 约束 | 形状 |
| --- | --- | --- | --- | --- | --- |
| input_x | 输入 tensor | tensor | float16, float32 | 无 | (N,…)，ND 格式 |
| output | 输出 tensor | tensor | float16, float32 | 与 input_x 同 shape、同 dtype | (N,…)，ND 格式 |

计算公式：`output = 0.5 * input_x * (1 + erf(input_x / sqrt(2)))`

1.2.3 Gelu 算子功能分析
Gelu 算子功能：对输入张量逐元素计算 GELU 激活值。

- 输入：input_x（float16 / float32，ND 格式）
- 输出：output（与 input_x 同 shape、同 dtype）
- 支持数据类型：float16、float32
- 支持形状：任意维度（ND 格式），逐元素计算，不涉及广播
- 计算特性：element-wise 算子，输出与输入一一对应，无归约、无状态

2. 需求分析（required）

2.1 需求描述
使用 Ascend C 编程语言实现 Gelu 算子，支持 float16、float32 数据类型，逐元素计算 `gelu(x) = 0.5 * x * (1 + erf(x / sqrt(2)))`，输出 shape、dtype 与输入一致，性能不低于 TBE 版本。

2.2 需求拆解
1. 支持 float16、float32 数据类型（通过 tiling key 模板参数区分）
2. 支持任意维度 ND 格式输入（逐元素计算，视为一维向量处理）
3. 数学公式精确实现：`0.5 * x * (1 + erf(x / sqrt(2)))`，使用 Ascend C 内置 `Erf` 指令
4. 输出 shape、dtype 与输入 input_x 一致（InferShape / InferDataType）
5. 性能优化：多核并行（AIV 核均分）+ 双缓冲流水（CopyIn / Compute / CopyOut 重叠）+ 32B 对齐块分配
6. 无需额外 workspace（计算在 UB 内完成，输入输出双缓冲各占一份）

3. 详细设计（required）

3.1 算子分析

3.1.1 数学公式
```
output[i] = 0.5 * input_x[i] * (1 + erf(input_x[i] / sqrt(2)))
```
其中 `1 / sqrt(2) ≈ 0.70710678`（以 `inv_sqrt2` 常量预存）。

计算分解（kernel 侧 Compute 阶段）：
1. `tmp = x * inv_sqrt2`（即 x / sqrt(2)）
2. `tmp = erf(tmp)`
3. `tmp = tmp + 1.0`
4. `tmp = tmp * 0.5`
5. `output = tmp * x`

3.1.2 支持数据类型
| 参数 | 数据类型 | dtype 类型 |
| --- | --- | --- |
| input_x | float16 / float32 | DT_FLOAT16 / DT_FLOAT |
| output | float16 / float32（与输入一致） | DT_FLOAT16 / DT_FLOAT |

通过 tiling key 模板参数 `DT_INPUT_X`（`C_DT_FLOAT16` / `C_DT_FLOAT`）在编译期区分数据类型，kernel 侧以 `KernelGelu<DT_INPUT_X>` 模板类实例化。

3.1.3 支持形状
支持任意维度 ND 格式输入（(N,…)）；逐元素计算，host 侧将数据视为一维向量（仅考虑元素总个数 `length`），不涉及维度信息与广播。输出 shape 与输入完全一致。

3.2 算子实现

3.2.1 host 侧设计

tiling 策略：
本算子为 element-wise 逐元素计算，不涉及维度信息，host 侧将输入视为一维向量，仅考虑元素总个数 `length`。tiling 数据结构 `GeluTilingData` 包含：
- `length`：输入总元素个数
- `smallCoreDataNum` / `bigCoreDataNum`：小核/大核负责的元素个数
- `finalSmallTileNum` / `finalBigTileNum`：小核/大核需要处理的 tile 个数
- `tileDataNum`：每个 tile 的元素个数
- `smallTailDataNum` / `bigTailDataNum`：小核/大核最后一片 tile 的元素个数
- `tailBlockNum`：处理大块数据的核（大核）个数

任务均分：
核数 `num_cores_aiv` 由平台信息 `platform.GetCoreNumAiv()` 获取（≤0 时取 1），`context->SetBlockDim(num_cores_aiv)` 启动全部 AIV 核。输入长度按 32 元素（32B 对齐块，`kBlockSize=32`）向上对齐为 `aligned_length`，总块数 `block_count = aligned_length / 32`。每核基础块数 `base_blocks_per_core = block_count / num_cores_aiv`，余块 `extra_blocks = block_count % num_cores_aiv`。前 `extra_blocks` 个核为"大核"（多处理 1 个对齐块），其余为"小核"。

批量搬运：
每核内部按 `tileDataNum` 分片，通过双缓冲（`BUFFER_NUM=2`）将多次搬入/计算/搬出合并为流水操作，CopyIn 与 Compute 与 CopyOut 在 tile 间重叠，减少冗余开销。尾片（最后一片 tile 可能不足 `tileDataNum`）按 `tailDataNum` 处理，确保不完整块也能被合并到计算流程中，避免数据碎片。

1. 分核策略：
优先使用满核的原则（启动全部 AIV 核）。如果核间能均分（`extra_blocks=0`），可视作无大小核区分，大核小核数据一致；如果核间不能均分，余出的对齐块分配到前 `tailBlockNum` 个核上（大核）。输入数据大小计算：通过 `tensor_input_x->GetShapeSize()` 获取元素总个数，`ge::GetSizeByDataType(dtype)` 获取类型长度，计算总字节数。核心数量与 UB 内存大小通过平台信息获取。

2. 数据分块和内存优化策略：
充分使用 UB 空间的原则。考虑双缓冲（输入队列 inQueue + 输出队列 outQueue 各 `BUFFER_NUM=2` 份），可用 UB 取 `0.75 * ub_size`，单次 tile 元素数：
```
tile_data_num = available_ub / (2 * 2 * dtype_size)
```
（2 份双缓冲 × 输入输出各 1 份 × 类型字节数）。`tile_data_num` 不小于一个对齐块（32 元素），不超过 `aligned_length`，并向上对齐到 32 元素。每核 tile 数 `finalTileNum = ceil(coreDataNum / tileDataNum)`，尾片大小 `tailDataNum = coreDataNum % tileDataNum`（整除时为 `tileDataNum`）。

3. tilingkey 规划策略：
需要 tilingkey 的情况：需要感知 host 侧输入数据类型对 kernel 侧走不同模板实例化分支。host 侧通过 `ASCENDC_TPL_SEL_PARAM(context, dt_input_x)` 配置 tiling key，`dt_input_x = static_cast<uint32_t>(dtype_input_x)`；kernel 侧 `tiling_key_gelu.h` 中定义 `ASCENDC_TPL_ARGS_DECL(Gelu, ASCENDC_TPL_DATATYPE_DECL(DT_INPUT_X, C_DT_FLOAT16, C_DT_FLOAT))`，以 `DT_INPUT_X` 模板参数实例化 `KernelGelu<DT_INPUT_X>`，区分 float16 / float32 计算路径。

数据检测：
host 侧 TilingFunc 中：
- `num_cores_aiv <= 0` 时取 1（容错）
- `tile_data_num` 计算后兜底：小于 32 时取 32，为 0 时取 32，向上对齐到 32
- `small_core_data_num` / `big_core_data_num` 为 0 时对应 `finalTileNum` 取 0（避免除零）
- workspace 大小设为 0（本算子无需额外 workspace）
- InferShape：输出 shape 与输入 input_x 一致
- InferDataType：输出 dtype 与输入 input_x 一致

3.2.2 kernel 侧设计

进行 Init 和 Process 两个阶段，其中 Process 包括数据搬入（CopyIn）、计算（Compute）、搬出（CopyOut）三个阶段。

1. 数据类型处理：kernel 侧以模板参数 `DT_INPUT_X` 实例化，输入输出类型一致（`TYPE_X = TYPE_Y = DT_INPUT_X`）；`inv_sqrt2` 常量以 `static_cast<TYPE_X>(0.70710678)` 预存，避免运行时转换。float16 / float32 均直接以原类型计算（Ascend C `Erf` 指令支持 float16 / float32）。

2. CopyIn（数据搬入）：`Init` 阶段根据本核编号 `core_num = GetBlockIdx()` 计算全局起始偏移 `global_buffer_index`（大核在前按 `big_core_data_num` 步长，小核修正大核步长差量），设置 `xGm` / `yGm` 的 GlobalTensor 视图与本核 `coreDataNum`；初始化双缓冲队列 `inQueue` / `outQueue`（各 `BUFFER_NUM=2`，每片 `tileDataNum * sizeof(TYPE)`）。`CopyIn` 中从 `xGm[progress * tileDataNum]` 按 `current_tile_size` 搬入 `inQueue`。

3. Compute（计算）：逐 tile 执行 GELU 公式，使用 Ascend C 向量指令：
   - `Muls(yLocal, xLocal, inv_sqrt2, size)` → `x / sqrt(2)`
   - `Erf(yLocal, yLocal, size)` → `erf(x / sqrt(2))`
   - `Adds(yLocal, yLocal, 1.0f, size)` → `1 + erf(...)`
   - `Muls(yLocal, yLocal, 0.5f, size)` → `0.5 * (1 + erf(...))`
   - `Mul(yLocal, yLocal, xLocal, size)` → `0.5 * x * (1 + erf(...))`
   计算结果写入 `outQueue`，释放 `inQueue` 的输入片。

4. CopyOut（数据搬出）：从 `outQueue` 取出结果片，按 `current_tile_size` 写回 `yGm[progress * tileDataNum]`，释放输出片。

5. 流水与尾片处理：`Process` 中循环 `tileNum` 次，每次判断是否为最后一片（`i + 1 == tileNum`）以确定 `current_tile_size = tailDataNum`（其余为 `tileDataNum`）；双缓冲使相邻 tile 的 CopyIn / Compute / CopyOut 重叠，隐藏访存延迟。

3.4 算子约束限制
- 输入输出 dtype 必须一致（InferDataType 强制输出 dtype = 输入 dtype）
- 仅支持 float16、float32，不支持 int32、bfloat16 等其他类型
- 仅支持 ND 格式，不支持 5HD、NC1HWC0 等特定格式
- 逐元素计算，不涉及广播（输入输出 shape 必须一致）
- 无需额外 workspace（workspace_sizes[0] = 0）
- 数学公式使用 `erf` 精确实现，不使用 tanh 近似

4.2 兼容性分析
新增算子，不涉及对既有接口的破坏性修改；算子定义通过 `OP_ADD(Gelu)` 注册，输入名 `input_x`、输出名 `output`，与深度学习框架 GELU 算子的标准命名兼容；host 侧 InferShape / InferDataType 保证输出与输入同 shape 同 dtype，符合 element-wise 算子的通用预期；kernel 侧通过 tiling key 模板参数区分 dtype，后续扩展新数据类型（如 bfloat16）只需在 tiling_key 与 OpDef 中增加对应枚举，无需修改 kernel 计算逻辑。
