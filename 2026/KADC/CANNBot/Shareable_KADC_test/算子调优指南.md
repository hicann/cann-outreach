# Ascend C 算子调优指南

## 1. 调优方法论总览

```
Profiling 采集 → 瓶颈识别 → 按瓶颈分类优化 → 验证迭代
```

**核心原则**：数据驱动，先定位瓶颈再优化，避免凭直觉盲改。

---

## 2. 瓶颈识别

通过 Profiling 数据分析 `PipeUtilization.csv` 中各单元的时间占比，确认主导瓶颈。

### 2.1 瓶颈分类速查

| 瓶颈类型 | 判定条件 | 优化方向 |
|---------|---------|---------|
| **VEC Bound** | `aiv_vec_ratio` 最高且 >50% | 减少计算量、UB 融合、融合指令 |
| **MTE2 Bound** | `ai*_mte2_ratio` 最高 | 增大搬运粒度、地址对齐、DoubleBuffer |
| **CUBE Bound** | `aic_cube_ratio` 最高 | L0C 累加、L1 复用、AtomicAdd |
| **SCALAR Bound** | `ai*_scalar_ratio` >30% | 缩小 TilingData、减少核数 |
| **流水线气泡** | 多单元均在 30-50%，无明显主导 | 增加 workspace、DB、异步迭代 |
| **核间不均衡** | 各核耗时差异 >10% | 均匀分配尾块、调整 Block Dim |

### 2.2 交叉关联诊断

| 现象组合 | 根因 | 优化方向 |
|---------|------|---------|
| 高 vec_ratio + 高 bank_cflt | Bank conflict 放大了 VEC 耗时 | 先解决 bank conflict |
| 高 mte2_time + 低 L2 hit rate | L2 缓存未命中导致搬运慢 | 设置 CacheMode |
| 高 fixpipe_ratio | 地址未 512B 对齐 | 调整 GM 地址对齐 |
| 高 mte2 + 高 mte3 | 双向搬运饱和 | 增大 tile 减少搬运次数 |
| 低 Block Dim + 高 Duration | 核数不足 | 增加 Block Dim |
| 各核耗时差异大 + Block Dim 合理 | Tiling 切分不均 | 调整 Tiling 均匀分配 |
| Current Freq < Rated Freq | DVFS 降频 | 增加 warm-up 或检查散热 |

## 3. VEC Bound（Vector 计算瓶颈）优化

### 3.1 严重程度

- **50-65%**：轻度，DoubleBuffer + UB 融合有较大收益
- **65-80%**：中度，需减少 Cast 或融合指令
- **>80%**：深度，VEC 接近理论极限，优化空间有限

### 3.2 优化方法（按优先级）

| # | 方法 | 预期收益 | 适用条件 |
|---|------|---------|---------|
| 1 | **UB 融合** | 20-50% | 多步计算间有 GM 往返 |
| 2 | **减少 Cast** | 10-30% | fp32 ratio 远高于预期（大量 fp16→fp32 转换） |
| 3 | **融合指令** | 5-15% | 存在 mul+add、mul+sub 等可融合序列 |
| 4 | **低延迟归约** | 10-20% | 有 ReduceSum/Max 操作 |
| 5 | **AIC:AIV = 1:2** | 30-40% | MatMul 后带 Vector 后处理 |
| 6 | **Counter 模式** | 5-10% | 循环内有条件判断 |

### 3.3 UB 融合

将多次 GM↔UB 往返合并为一次，减少带宽压力：

```
未融合: GM→UB→Compute1→UB→GM→UB→Compute2→UB→GM  // 6 次 GM 访问
已融合: GM→UB→Compute1→Compute2→UB→GM             // 2 次 GM 访问
```

### 3.4 减少 Cast

- 如果算子精度允许，直接用 fp16 计算避免 fp16→fp32 转换
- 必须转换时，尽量批量一次转换，避免逐元素 Cast

## 4. MTE2 Bound（搬入瓶颈）优化

### 4.1 先判断是否已达理论带宽

```
理论 MTE2 耗时 = GM_to_UB_datas(KB) × 1024 / GM_峰值带宽(Byte/s)
实际 MTE2 耗时 = ai*_mte2_time(us)

if 实际 ≈ 理论 (差异<20%):
    MTE2 已达上限 → 优化方向是流水编排（掩盖搬运）
else:
    MTE2 未达上限 → 检查搬运效率
```

### 4.2 优化方法

| # | 方法 | 适用条件 | 检查方式 |
|---|------|---------|---------|
| 1 | **增大单次搬运量** | 单次 <16KB | 计算 `GM_to_UB_datas / mte2_instructions` |
| 2 | **512B 地址对齐** | `fixpipe_ratio >5%` | 检查 `aic_fixpipe_ratio` |
| 3 | **L2 CacheMode** | L2 hit rate <50% | 检查 `L2Cache.csv` |
| 4 | **避免同地址访问** | 多核读同一地址 | 检查各核 `mte2_time` 差异大 |
| 5 | **DoubleBuffer** | MTE2 和 VEC 串行 | 流水图显示无重叠 |
| 6 | **增大 Tile 尺寸** | 搬运次数过多 | `mte2_instructions` 过大 |

### 4.3 L2 Cache 优化

| # | 方法 | 说明 |
|---|------|------|
| 1 | **设置 CacheMode** | `SetL2CacheHint(CacheMode::CACHE_MODE_NORMAL)` 启用 L2 缓存 |
| 2 | **禁用不需要的缓存** | 只读一次的数据设置 `CACHE_MODE_DISABLE` 避免污染 L2 |
| 3 | **L2 Cache 切分** | 合理规划数据搬运顺序，提高数据局部性 |
| 4 | **较小矩阵驻留 L1** | MatMul 场景中，让 B 矩阵驻留 L1，减少 GM 访问 |

## 5. CUBE Bound（矩阵计算瓶颈）优化

| # | 方法 | 说明 |
|---|------|------|
| 1 | **L0C 累加** | 利用 L0C 做多次矩阵乘法的累加，减少搬运 |
| 2 | **L1 数据复用** | 合理 Tiling 使 A/B 矩阵驻留 L1，减少 GM 访问 |
| 3 | **BT Buffer** | 使用 BT Buffer 实现高效 bias 计算 |
| 4 | **FP Buffer** | 使用 FP Buffer 存放量化参数 |
| 5 | **AtomicAdd** | Matmul 使能 AtomicAdd 选项优化多核 |

## 6. SCALAR Bound（标量计算瓶颈）优化

通常出现在数据量很小、头开销占比大的场景。

| # | 方法 | 说明 |
|---|------|------|
| 1 | **缩小 TilingData** | 减少不必要字段，TilingData 越大搬运越慢 |
| 2 | **减少核数** | 数据量小时，少核 = 少头开销 |
| 3 | **TPipe 外置** | 避免 TPipe 在对象内创建和初始化 |
| 4 | **移出不变量** | 循环不变的计算移到 Host 侧 |

### 头开销参考值

| 平台 | 满核头开销 | 说明 |
|------|----------|------|
| Atlas A2 | ~20-21 us | 包含核启动 + TLB + 初始化 |

如果 Task Duration 中头开销占比 >30%，说明数据量太小或核数太多。

## 7. 核间负载不均衡优化

### 7.1 诊断

```python
# 从 PipeUtilization.csv 提取各核耗时
times = [row['aiv_time(us)'] for row in pipe_rows]
imbalance = (max(times) - min(times)) / max(times) * 100

if imbalance < 10:   print("均衡")
elif imbalance < 30:  print("不均衡，调整 Tiling")
else:                 print("严重不均衡，优先修复")
```

### 7.2 优化方法

| 方法 | 说明 |
|------|------|
| **均匀分配尾块** | 数据总量不能被核数整除时，将尾块分散到更多核 |
| **调整 Block Dim** | 选择能整除数据量的核数 |
| **尾块调整策略** | kernel 中动态计算尾块的实际大小，而非用满块大小搬运 |

### 7.3 尾块正确处理

```cpp
// 方式1：循环内动态计算尾块大小
for (uint32_t k = 0; k < totalK; k += BLOCK_SIZE) {
    uint32_t actualSize = (k + BLOCK_SIZE <= totalK) ? BLOCK_SIZE : (totalK - k);
    DataCopyPad(dst, src[k], actualSize);
}

// 方式2：先计算 loops，循环末尾单独处理尾块
uint32_t kLoops = (totalK + BLOCK_SIZE - 1U) / BLOCK_SIZE;
uint32_t kBlockSize = BLOCK_SIZE;
for (uint32_t i = 0; i < kLoops; i++) {
    if (i == kLoops - 1U) {
        kBlockSize = totalK - (kLoops - 1U) * BLOCK_SIZE;
    }
    DataCopyPad(dst, src[i * BLOCK_SIZE], kBlockSize);
}
```

## 8. Bank Conflict 优化

### 8.1 判定

`ResourceConflictRatio.csv` 中 `aiv_vec_total_cflt_ratio` >5%

### 8.2 UB Bank 结构

- UB: 48 个 bank，分为 16 个 group（每组 3 个 bank）
- 每个 bank 32 Bytes 宽
- 同时读写同一 bank → bank conflict
- 同时读同一 bank group 的不同 bank → bankgroup conflict

### 8.3 按冲突类型优化

| 冲突类型 | 判定字段 | 原因 | 优化 |
|---------|---------|------|------|
| **bankgroup** | `vec_bankgroup_cflt_ratio` >3% | block_stride 设置不合理 | 修改 Vector API 的 `repeatStride`/`blockStride` 参数 |
| **bank** | `vec_bank_cflt_ratio` >3% | 操作数读写指针地址不合理 | 调整 UB tensor 起始地址，添加 padding（32B 整数倍间隔） |
| **资源** | `vec_resc_cflt_ratio` >5% | 多个计算单元争抢同一执行单元 | 错开 Vector/Cube 调度 |
| **MTE** | `vec_mte_cflt_ratio` >3% | Vector 和 MTE 竞争共享资源 | 调整数据搬运和计算时序 |

## 9. DoubleBuffer 优化

### 9.1 原理

```
时间 →
Buffer 0: [MTE2搬运]──[Vector计算]──[MTE3写出]
Buffer 1:        [MTE2搬运]──[Vector计算]──[MTE3写出]
                  ↑ 搬运和计算并行！
```

### 9.2 检查清单

| # | 检查项 | 正常值 |
|---|-------|-------|
| 1 | `InitBuffer` 的 `bufNum` 参数是否为 2 | 必须为 2 |
| 2 | EnQue/DeQue 是否正确配对 | 每次循环都有 |
| 3 | 循环内是否有不必要的 Sync | 应避免 |
| 4 | 数据依赖是否阻止了并行 | 检查前后 tile 是否有依赖 |

### 9.3 效果验证

| 状态 | MTE2 和 VEC 重叠比例 |
|------|---------------------|
| DB 生效 | >30% |
| DB 部分 | 10-30% |
| DB 未生效 | <5% |

### 9.4 使用方式

```cpp
constexpr uint32_t BUFFER_NUM = 2;  // 双缓冲
pipe.InitBuffer(inQueueX, BUFFER_NUM, tileLength * sizeof(T));
pipe.InitBuffer(inQueueY, BUFFER_NUM, tileLength * sizeof(T));
pipe.InitBuffer(outQueue, BUFFER_NUM, tileLength * sizeof(T));
```

**适用条件**：数据量较大（>8K 元素）、搬运和计算时间相当、UB 容量允许双缓冲。

## 10. 流水线气泡优化

多个单元均在 30-50% 占比，无明显主导单元时，说明存在流水线气泡。

| # | 方法 | 说明 |
|---|------|------|
| 1 | **增加 workspace 份数** | 从 2 份增到 4 份，减少 Cube/Vector 互等 |
| 2 | **DoubleBuffer** | 使搬运和计算并行 |
| 3 | **异步迭代** | 使用 IterateAll/EnQueAll 减少同步开销 |
| 4 | **AIC:AIV 比例调整** | Cube 和 Vector 耗时不匹配时调整启动比例 |

## 11. 通用代码级优化规范

### 11.1 循环内禁止逐元素操作

逐元素 API 调用会产生严重的调用开销：

```cpp
// 错误：循环内逐行调用 API
for (uint32_t r = 0; r < R; r++) {
    AscendC::Sub<float>(xLocal[r * alignedCols], xLocal[r * alignedCols],
                        tmpLocal, cols);
}

// 正确：使用批量操作
AscendC::Sub<float>(xLocal, xLocal, tmpLocal, totalSize);
```

### 11.2 禁止写死硬件参数

```cpp
// 错误：写死核数
uint32_t blockDim = 24;

// 正确：动态获取
uint32_t blockDim = GetBlockDim();
```

### 11.3 减少冗余 PipeBarrier

连续 Vector 操作之间不需要 PipeBarrier（硬件保序），只在跨 Pipe 依赖时才需要：

| 场景 | 是否需要 Barrier |
|------|-----------------|
| DataCopy(GM→UB) 后 Vector 计算 | 需要（通过 EnQue/DeQue） |
| Vector 计算后 DataCopy(UB→GM) | 需要（通过 EnQue/DeQue） |
| 连续 Vector 操作 | 不需要（硬件保序） |
| Reduce 后读标量 | 需要 |

### 11.4 单次搬运量 >= 16KB

```cpp
constexpr uint32_t TILE_SIZE = 16 * 1024 / sizeof(float);  // >= 16KB
```

### 11.5 避免 GM 重复读取

在 UB 中缓存数据，避免对同一 GM 地址多次 DataCopy。

### 11.6 流水线同步正确性

DataCopy 是异步 DMA，必须通过 EnQue/DeQue 同步：

```cpp
// Step 1: CopyIn
LocalTensor<float> xLocal = inQueueX.AllocTensor<float>();
DataCopyPad(xLocal, xGm[gmOffset], copyParams, padParams);
inQueueX.EnQue(xLocal);                    // 标记就绪

// Step 2: Compute
LocalTensor<float> xIn = inQueueX.DeQue<float>();  // 阻塞等待 MTE2 完成
Adds<float>(yLocal, xIn, 1.0f, count);
outQueueY.EnQue(yLocal);

// Step 3: CopyOut
LocalTensor<float> yOut = outQueueY.DeQue<float>();  // 阻塞等待 Vector 完成
DataCopyPad(yGm[gmOffset], yOut, copyParams);
```

### 11.7 FP16 中间精度保护

FP16 精度有限（约 3 位有效数字），累加/归约操作应使用 FP32 中间结果：

```cpp
// 正确：使用 FP32 累加
float sum = 0;
for (int i = 0; i < N; i++) {
    sum += (float)data[i];  // FP32 累加
}
half result = (half)sum;  // 最后转回 FP16
```

## 12. Tiling 设计优化

### 12.1 多核切分策略

- 负载均衡：每个核处理的任务量尽量相等
- 数据局部性：相邻数据尽量分配给同一核
- 粒度适中：tile 不能太小（调度开销大），不能太大（并行度低）

```cpp
// 均匀切分 + 处理余数
uint32_t totalLength = ...;
uint32_t blockDim = GetBlockDim();
uint32_t avgLength = totalLength / blockDim;
uint32_t remainder = totalLength % blockDim;

uint32_t tileLength = avgLength + (blockIdx < remainder ? 1 : 0);
uint32_t offset = blockIdx * avgLength + std::min(blockIdx, remainder);
```

### 12.2 片上缓存容量约束

各级缓存容量固定，Tiling 时必须确保不超限：

| 缓存 | 所属核 | 典型容量 | 用途 |
|------|-------|---------|------|
| **UB** | Vector Core | 256 KB (DAV_3510) | 向量计算缓冲 |
| **L1** | Cube Core | 512 KB (DAV_3510) | GM→L1 数据缓存 |
| **L0A** | Cube Core | 64 KB | 矩阵左输入 |
| **L0B** | Cube Core | 64 KB | 矩阵右输入 |
| **L0C** | Cube Core | 256 KB | 矩阵乘输出 |

- **纯向量算子**：所有 `InitBuffer` 的 `bufferNum × bufferSize` 之和不超过 UB 容量
- **矩阵算子**：额外检查 L1、L0A/L0B/L0C 各级分配

### 12.3 Buffer 规划原则

| Buffer 类型 | 推荐配置 |
|------------|---------|
| 输入 Buffer | 2 个（Double Buffer） |
| 输出 Buffer | 2 个（Double Buffer） |
| 临时 Buffer | 按需分配 |
| Reduce 临时 Buffer | 额外分配 |

## 13. MatMul 专项优化

### 13.1 模板选择决策

```
MatMul 需求
    │
    ├── 通用场景（默认）
    │       └── 纯AIC — 适用大多数 shape
    │
    ├── M·N 欠并行且长 K（≥4096）
    │       └── StreamK — K 维切分填满空闲核
    │
    └── 需要 AIC/AIV 流水重叠、epilogue 可定制
            └── FixpOpti — Fixpipe→UB 后由 AIV MTE3 写回
```

### 13.2 Mode 选择

| Mode | 适用场景 | 说明 |
|------|---------|------|
| **NO_FULL_LOAD**（默认） | 通用 | A、B 每轮从 GM→L1 |
| **A_FULL_LOAD** | `Align(m,16)·Align(k,16)·sizeof(A) ≤ ~256KB` 且 N ≥ 1024 | A 首轮搬入驻留 L1 |

### 13.3 关键优化技术

| 优化技术 | 预期收益 | 关键前提 |
|---------|---------|---------|
| **A_FULL_LOAD / B_FULL_LOAD** | -5%~-15% | 对侧循环 T≥2 + 真 MTE2 bound |
| **StreamK** | 核利用率提升到接近 100% | K≥4096 + workspace 开销可接受 |
| **FixpOpti** | MTE3 写回延迟被 AIC 计算隐藏 | 多 tile 场景 + MTE3 是瓶颈 |
| **L1 stage 2→4** | MTE2/CUBE overlap 提升 | L1 容量充足 |
| **AIC:AIV = 1:2** | 29%+ | Cube 和 Vector 耗时严重不匹配时 |

### 13.4 MatMul 三级流水

| 级别 | Buffer 数 | 事件类型 | 说明 |
|------|----------|---------|------|
| L1 | 2（双缓冲） | MTE1↔MTE2 | A/B 矩阵在 L1 中轮换 |
| L0A/L0B | 2（隐式 ping-pong） | M↔MTE1 | 矩阵分形载入 L0 |
| L0C | 1 或 2 | fixpipe 内部串行 | 累加输出 |

### 13.5 MatMul 精度常见陷阱

| 现象 | 根因 | 修复 |
|------|------|------|
| fixpipe 写回全 0 | `cmatrixInitVal` 每轮都为 true | 首拍 true，后续 false |
| ≈100% mismatch | launcher 里 layout 硬编码未跟 trans 同步 | layout 与 trans 标志联动 |
| 精度偏大 | `kL1` 非 `baseK` 整数倍 | 确保 kL1 是 baseK 整数倍 |
| 大 K 退化 | baseK 过小，bf16 累加误差累积 | 增大 baseK 或 `dbL0c=2` |
| 单 tile PASS，多 tile FAIL | L0C ping-pong 半区重叠 | `HALF_L0C_SIZE` 不能多除 sizeof |
